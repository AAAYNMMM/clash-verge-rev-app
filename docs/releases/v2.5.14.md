# Clash Verge Rev App v2.5.14

**Windows x64 · Stable release**

[Latest release](https://github.com/AAAYNMMM/clash-verge-rev-app/releases/tag/v2.5.14) · [Routing architecture](../APP_ROUTING.md) · [Source](https://github.com/AAAYNMMM/clash-verge-rev-app/tree/dev)

## Routing model

- APP Rule-mode groups compile an independent copy of the active profile’s domain rules, nested sub-rules, and proxy groups.
- APP proxy-group node selections are persisted separately from the TUN default Rule-mode selections.
- Domains matching DIRECT remain direct. Other APP requests use APP-specific proxy selectors, without falling through to the TUN policy.
- TUN traffic not captured by an enabled APP group continues to use the configured native Rule, Global, or Direct exit.
- Fixed-node APP groups, process matching priority, loopback and local-address protection, and the disabled-system-proxy requirement are unchanged.

## Distribution

- Windows x64 NSIS installer with SHA-256 checksum and Tauri updater signature.
- Independent service, IPC identity, installation location, and profile storage remain isolated from upstream Clash Verge Rev.
- v2.5.13 remains available as a historical prerelease; its installer does not contain the independent APP rule selectors.
- GitHub Actions release templates no longer include inherited referral advertising.

## Verification boundary

- Test scope: frontend type checking, targeted tests, service compilation, packaging integrity, and metadata path checks.
- Application update signatures authenticate downloads; they are not Windows Authenticode signatures.
- Complete end-to-end TUN routing across network adapters and third-party subscriptions is not guaranteed by isolated compiler tests.
