## Release surface

The published executable includes the independent Windows service and the TUN-scoped APP override compiler. The APP overlay composes ordered process predicates with native Rule / Global / Direct egress; pinned node identities fail closed, and node candidate filtering uses bounded `fancy-regex`. The service protocol handshake has been corrected and the installer updates an existing instance of the fork-owned service rather than reusing a stale binary.

Installer and service namespace are independent of upstream Clash Verge Rev. APP overrides apply to `IN-TYPE,TUN` only; explicit HTTP/SOCKS traffic follows the native mode. The implementation does not provide tab-scoped routing or inherited process ownership.

## Validation boundary

The Windows installer was executed successfully, and a real service handshake and managed Mihomo startup were observed. The routing compiler was validated with a real Mihomo parser and isolated ingress substitution. Complete end-to-end TUN behavior across real network adapters was not verified. An automation-host WebView2 startup attempt returned `0x80070005`; the service and core started despite that UI-host error.

The release artifacts preserve the audited `2.5.13` binary bytes; documentation changes do not alter or rebuild the installer.

The v2.5.13 Windows test installer was republished without changing the application version to remove embedded local Rust build paths. Runtime routing semantics are unchanged.
